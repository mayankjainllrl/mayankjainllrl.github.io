// 02 · how I think

Six ways real systems break, and how I design them out

Every one of these came up on a real platform I built. They're live: pick one and try to break it.

A user taps "Pay" three times on a slow network

A naive backend sees three requests and charges three times. Mine sends an idempotency key and stores it under a unique constraint, so retries return the original charge, even when they arrive in the same millisecond.

  1. Press Pay $100 once.
  2. Now press it again a few times, fast.
  3. Compare what each backend charged.
WHERE I'VE FIXED THISPayouts that close exactly once when two webhooks arrive together, retry-safe document generation, and a notifier that once sent triple emails, rewritten to claim each job exactly once.

Someone quietly edits a signed agreement

Signing a document takes its fingerprint (a SHA-256 hash) and locks it with a private key. Change even one character and the fingerprint no longer matches, so the edit gets caught.

  1. Press Sign.
  2. Press Change the amount, or edit any text yourself.
  3. Watch the check fail. Undo it and it passes again.

Splitting money between people

$200 split three ways is $66.666… each, but money only has cents. Round every share up and you pay out money you don't have. Round down and a cent disappears. Mine counts in whole cents and hands out the leftover on purpose.

  1. Pick a split below.
  2. Compare the total paid out at the bottom of each side.
WHERE THIS COMES FROMI found floating-point errors in real payout splits and fixed them, and made currency conversions round down to the cent so a payout can never be larger than the balance behind it.

// 06 · open source

The double-charge fix, in real code

PayFlow ↗

A payments service on a modern async stack, built around the parts that break in real payment systems.

  • Idempotency with a unique constraint, so two simultaneous retries can't both charge.
  • Double-entry ledger written in one atomic transaction.
  • Async integration tests against real Postgres, in GitHub Actions CI.
FastAPIPostgreSQLSQLAlchemy 2.0AlembicDockerpytest
# two requests, same key, same millisecond:
# the database decides who wins, not the app
try:
    session.add(Payment(idempotency_key=key, amount=amount))
    await session.commit()
except IntegrityError:
    await session.rollback()
    # the other request won the race;
    # return its payment instead of charging again
    existing = await session.scalar(
        select(Payment).where(Payment.idempotency_key == key)
    )
    return existing
